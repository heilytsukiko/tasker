# Архитектура фронтенда Tasker

Стек: React 19 + TypeScript (strict) + CSS Modules, сборка Vite, роутинг React Router.
Backend (Node.js + Express, PostgreSQL) — отдельный репозиторий; фронт общается с ним только по REST/JSON.

## Структура папок

Слои сверху вниз; **импортировать можно только из слоёв ниже** (страница → виджет → сущность → shared).

```
src/
  app/        инициализация: App, router, layouts (MainLayout), в будущем providers (Auth)
  pages/      страницы-маршруты; каждая — папка с index.ts (публичный вход) и ui/ с секциями
  widgets/    крупные самостоятельные блоки интерфейса (header, footer, позже — таблицы кабинетов)
  features/   пользовательские сценарии (login, register, create-review, submit-report…) — появятся со спринта 2
  entities/   бизнес-сущности: модель + UI-карточки (promotion; позже company, review, report)
  shared/     всё без бизнес-логики
    ui/       базовые компоненты (Button, Chip, Container, Logo, StarRating)
    api/      http-клиент (fetch + JWT), типы и enum-значения из схемы БД
    config/   routes, env
    lib/      утилиты (cn)
  styles/     tokens.css (токены Figma), fonts.css, global.css
```

Правила:

- Компонент = папка: `Component.tsx`, `Component.module.css`, `index.ts` (если нужен публичный вход).
- Стили только через CSS Modules и **переменные из `styles/tokens.css`**. Цвет, отступ, радиус, размер шрифта — токеном. Числа вне шкалы токенов допустимы только для пиксельной подгонки под макет и комментируются.
- Алиас `@/` → `src/`. Внутри слайса — относительные пути, между слайсами — через `@/` и публичный `index.ts`.
- Адреса и якоря — только из `shared/config/routes.ts`.
- Ответы API типизируются в `shared/api` или в `model/` сущности; `any` не используем.

## Дизайн-токены (Figma → код)

Источник правды — коллекция переменных **Tasker Tokens** в Figma (файл Tasker). В коде они зеркалятся в
`src/styles/tokens.css`: `color/bg/surface` → `--color-bg-surface`, `space/16` → `--space-16`,
`radius/28` → `--radius-28`, `font-size/14` → `--font-size-14`.

Порядок обновления: изменили в Figma → прочитали `get_variable_defs` по фрейму → обновили `tokens.css` в том же коммите, что и компоненты.

## Работа с макетами

1. Берём ссылку на фрейм с `node-id`.
2. Читаем структуру и скриншот (`get_design_context`), переводим в Flex/Grid и CSS Modules, подставляя токены.
3. Сверяем с макетом по скриншоту и по координатам ключевых блоков (ширина 1440, контент 1280, поля 80).
4. Статические ассеты (фото, логотип, иконки) выгружаются из Figma в `src/assets/` с именами из `src/assets/README.md`
   и подхватываются через `findAsset('имя')` (`shared/lib/assets.ts`); нет файла — компонент показывает заглушку.

## Роли и доступ (план)

Три роли (`user`, `company`, `admin`) приходят из JWT. На спринте 2 добавляются `AuthProvider` в `app/providers`
и обёртка маршрута `RequireRole`; кабинеты живут под `/cabinet/user`, `/cabinet/company`, `/admin`.
Токен хранится в `localStorage` (`shared/api/client.ts`), клиент подставляет `Authorization: Bearer …`.

## Карта экранов по спринтам

| Спринт | Страницы |
| --- | --- |
| 1 | Каркас, токены, UI-кит, **лендинг** |
| 2 | Авторизация и регистрация (пользователь и компания) |
| 3 | Каталог акций, страница акции, кабинет пользователя (история, отзыв с фото, жалоба), кабинет компании |
| 4 | Кабинет администратора (жалобы, проверка компаний), доработки |

## Что зависит от backend

- Контракт API (эндпоинты, формы ответов) согласуем до спринта 3; до этого лендинг работает на моках (`pages/landing/model/mock.ts`).
- Загрузка фото отзыва: multipart на `uploads`, JPG/PNG/WEBP до 5 МБ — клиентская проверка типа и размера дублирует серверную.
